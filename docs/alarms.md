# 报警

报警的流程是:

```text
数据 → 判定 → 状态 → 决策 → 通知
```

设计原则只有一句话:**宁可晚报,不可误报。** 报警疲劳比漏报更快摧毁信任,延时确认、迟滞和分组都为此服务。

## 生命周期

每条报警都有状态:

```text
正常 → 观察中 → 触发 → 已确认 → 已恢复 → 正常
```

| 状态 | 含义 |
|---|---|
| 观察中 | 值已异常,但持续时间不够。过滤毛刺的关键 |
| 触发 | 异常持续够久,灯亮、响铃、发通知 |
| 已确认 | 有人看过了,灯不再闪,声音停止,不再提醒 |
| 已恢复 | 值回到恢复阈值之内,并持续够久 |

**只有状态变化才产生事件。** 一条持续一小时的报警只产生几个事件,不是几千个。

## 规则

在设置界面(`,`)编辑,或写在 `modules.conf`:

```text
alert = cpu.usage > 90 clear 80 for 30s clearfor 60s priority high
alert = disk.queue_depth{device=sda} >= 32 priority medium
```

| 部分 | 默认 | 含义 |
|---|---|---|
| 比较 | 必填 | `>` `>=` `<` `<=` |
| `clear V` | 阈值的 10% 以内 | 恢复阈值,必须比触发更宽松,这就是迟滞 |
| `for Ns` | 15s | 持续多久才触发 |
| `clearfor Ns` | 30s | 恢复后持续多久才算恢复 |
| `priority` | medium | `high`、`medium`、`low` |

可用的指标用 `procwatch --dictionary` 查看。

内置规则(可在设置中关闭):

| 规则 | 优先级 |
|---|---|
| CPU 使用率 > 90%,持续 60 秒 | 中 |
| 内存 > 90%,持续 60 秒 | 中 |
| 内存 > 97%,持续 30 秒 | 高 |
| 磁盘 > 90%,持续 60 秒 | 中 |
| 磁盘 > 97%,持续 30 秒 | 高 |
| 每秒新建 TCP 连接 > 500,持续 30 秒(Linux) | 中 |
| procwatch 自身 CPU > 25%,持续 60 秒 | 低 |

攻击发现直接进入“触发”,不经过观察。严重和高级发现会一直保持到有人确认;中级 30 分钟、低级 10 分钟后自动结束。

所有持续时长都用单调时钟,改系统时间不会触发或恢复任何报警。

## 决策:该不该打扰人

| 机制 | 行为 |
|---|---|
| 不重复 | 同一问题持续存在时只提醒:高级 5 分钟一次,中级 30 分钟一次,低级不提醒 |
| 合并 | 10 秒内同一台机器的多条报警,第一条立即发,其余合并成一条 |
| 压制 | 模块信号丢失时,不再报它名下的指标 |
| 维护 | 按时间窗口暂停,到期自动恢复 |
| 确认 | 确认后不再提醒 |

## 三级优先级

灯和声音采用 IEC 60601-1-8,即病人监护仪遵循的医用报警国际标准。

| 优先级 | 灯 | 声音 | 重复 | 对外通知 |
|---|---|---|---|---|
| 高 | 红色,约 2 Hz 快闪 | 10 个脉冲(3+2 节奏两组) | 每 10 秒 | 是 |
| 中 | 黄色,约 0.6 Hz 慢闪 | 3 个脉冲 | 每 25 秒 | 是 |
| 低 | 青色,常亮 | 2 个脉冲 | 只响一次 | 否 |

**说明:** 你要求参考迈瑞监护仪。这里用的是监护仪共同遵循的 IEC 标准的颜色、闪烁频率和脉冲节奏,声音由程序合成,不是迈瑞的录音。没有与真机对比过,实际音色会有差别。

## 报警灯

右上角的矩形就是报警灯,旁边显示报警内容。终端高度不足 20 行或宽度不足 70 列时,灯会隐藏,报警仍在 `#` 列表里。

| 按键 | 功能 |
|---|---|
| `!` | 确认全部 |
| `@` | 暂停声音,默认 120 秒,灯继续闪 |
| `#` | 报警列表,`Enter` 确认单条 |

灯上的 `♪off` 表示声音已关闭。

声音用系统播放器:macOS 的 `afplay`,Linux 的 `paplay`、`pw-play` 或 `aplay`,Windows 的 PowerShell。都没有时用终端响铃。

## 可靠性

**报警事件不会丢。** 采样数据走有界的事件总线,压力大时可以丢;报警走独立的通道,队列不限长。这个通道是安全的,因为引擎只在状态变化时才说话,而状态很少。

**报警不拖累采集。** 判定在自己的线程,通知在另一个线程。webhook 卡住不影响判定,判定也不影响采集。

**监护仪自己也被监护。** 下面这些指标都可用于规则和 Prometheus:

| 指标 | 含义 |
|---|---|
| `alarm.firing` | 当前触发数 |
| `alarm.notify_failed` | 通知失败数 |
| `alarm.eval_ms` | 评估耗时 |
| `kernel.bus_dropped` | 总线丢弃数 |
