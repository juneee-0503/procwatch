# 调查与证据

## 统一模型

所有来源的事件都带有实体(进程、文件、网络、持久化)、关系和依据:

- **Observed**:procwatch 看到的时间,真实发生时间最多早一个采样周期,界面用 `~` 标记。
- **Event**:操作系统记录的时间。

进程实例用 `pid + 启动时间` 标识,PID 复用不会把两个进程混为一谈。

## 案件

Case 页(`0`)管理一个案件目录 `procwatch-case-时间戳/`:

| 键 | 作用 |
|---|---|
| `n` | 新案件 |
| `c` | 采集 |
| `s` | 封存清单 |
| `v` | 校验 |
| `a` | 笔记 |
| `C` | 结论 |
| `i` | 生成网络隔离脚本(不执行) |
| `I` | IOC 扫描 |
| `Y` | 内容扫描 |
| `X` | 导出 STIX、MISP、ECS |

### 证据完整性

- **保管链**:`custody.log` 每条记录含前一条的哈希,任何修改、删除、重排都能被发现。
- **证据登记**:`evidence.json` 记录每个文件的哈希、来源、方法和缺口。
- **不覆盖**:同名证据重新采集时,旧文件移到 `evidence/earlier/` 并更新登记。
- **封存**:`manifest.json`、`seal.json` 固定某一时刻的内容。

哈希链能发现修改,但不能证明没有被完整重写。把封存时显示的链头记录到案件之外的地方,才有防篡改的意义。

## 隔离区

`Q` 把文件移入案件的 `quarantine/`,去掉全部权限并记录。恢复时会校验:

- 记录指向的路径确实在隔离区内。
- 文件哈希与记录一致。
- 原路径是绝对路径且没有被占用。

案件目录可能来自别处,记录内容一律不被信任。内容相同、来自不同位置的文件分别保存,都能恢复。

## 网络隔离

`i` 生成隔离和恢复脚本,**不执行**。错误的防火墙规则可能切断你和被调查主机的连接,由人审阅后运行。管理地址必须是合法的 IP 或 CIDR。

## 离线分析

```bash
procwatch --offline procwatch-case-… --artifacts ./copied-evidence --iocs iocs.txt
```

对已采集的案件重新运行 Sigma、YARA 和 IOC 规则,不需要原始系统。可解析的工件:EVTX、Prefetch、ShimCache、Amcache、注册表 hive。单个工件上限 1 GB。

## 分析样本

`--run` 真实运行程序。**只在隔离、可重置的虚拟机中使用。** 确认页面会再次提醒。它在第一条指令前暂停程序,接上深度追踪后再放行,所以能看到全部子进程。

## 导出格式

| 格式 | 内容 |
|---|---|
| STIX 2.1 | 指标,模式经 `stix2` 校验 |
| MISP | 事件和属性 |
| ECS JSON 行 | 时间线、活动 |
| CSV | 时间线、进程表 |
| Markdown / HTML | 案件报告 |
