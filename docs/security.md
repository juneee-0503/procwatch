# 安全与自保护

目标:遇到恶意程序时,procwatch 难以被终止或篡改,被破坏时一定能被发现,事后可以恢复和取证。

**对普通进程防御,对管理员留痕并由外部发现,对内核级攻击承认不可防。**

| 等级 | 攻击者 | 目标 |
|---|---|---|
| A | 与用户同权限的进程 | 防得住 |
| B | 管理员、root | 无法阻止,但必须被发现 |
| C | 内核级 | 本地不可防,依赖外部监控兜底 |

不做:内核级 rootkit 的本地防护、隐藏自身进程、挂钩系统调用、内核驱动自保、PPL 签名方案、在程序里硬编码密钥。

**未经验证的防护视为未实现。** 下面的状态都以验收用例为准。

## 防止被终止

服务以专用账户运行,普通用户无权向它发信号。拉起由服务管理器负责,程序自己不做。

看门狗只由主循环喂,而且只在核心模块最近真的采集过时才喂。独立线程无条件喂会让死掉的服务看起来还活着。

收到 SIGTERM 或服务停止时,先把原因写入日志并发给接收端,再有序退出。SIGKILL 无法拦截,由心跳消失兜底。

`systemctl stop` 被视为用户意图,不会拉起,由外部发现。

## 防止被篡改

**程序。** 启动时比对哈希,不一致就拒绝运行,升级后用 `--accept-program` 批准。能改写程序的攻击者可以一并绕过这个自校验,所以真正起作用的是心跳:哈希被带到本机之外比对。调试构建只警告。

**配置。** 记录每个文件的哈希。被改动时拒绝加载,沿用上一份已批准的副本,记入审计,并保留被改动的文件作证据。手工编辑后用 `--config-accept FILE` 批准,设置界面的保存会自动批准。

**日志。** 每条记录含上一条的哈希。修改、删除、插入都会破坏后面的链,校验会指出“自第 N 条起不可信”,之前的内容仍然可信。发现损坏时另存旧文件,开新链,不丢弃。

能写文件的攻击者可以重算整条链。对策是外部锚点:链头随心跳离开本机,启动时还发送历史上的一组点。改写后的链本地校验能通过,但和接收端保存的不一致。

删除封存段时保留它最后的哈希,证明这一段曾经存在。

## 外部发现

本机的一切保护在 B、C 面前都可能失效,所以必须有不依赖本机的手段。原则是**沉默即告警**。

在另一台机器上:

```bash
head -c 32 /dev/urandom | od -An -tx1 | tr -d ' \n' > heartbeat.key
```

```bash
procwatch --heartbeat-receiver 0.0.0.0:9190 --key heartbeat.key --period 15 --store logs/
```

在被监控的机器上,把同一个密钥放到只有服务账户能读的位置,然后配置:

```yaml
heartbeat:
  url: https://monitor.example.com/beat
  key_file: /etc/procwatch/heartbeat.key
  interval_seconds: 15
sync:
  url: https://monitor.example.com/logs
```

心跳含实例标识、递增序号、时间、程序哈希、配置哈希、日志链头,带 HMAC-SHA-256 签名。序号防重放,新实例标识用来区分重启和回放。

接收端报告:

| 事件 | 含义 |
|---|---|
| `lost contact` | 连续 3 个周期没有心跳。**需人工确认**,可能只是断网 |
| `restarted` | 新实例 |
| `last words` | 退出前的说明 |
| `program changed`、`configuration changed` | 哈希变了 |
| `log rewritten`、`log shortened` | 日志和锚点不符 |
| `replay` | 重放的心跳 |
| `refused beat` | 签名错误 |

接收端本身没有加密传输,跨网络时请放在 HTTPS 反向代理后面。

## 维护

```bash
procwatch --maintenance 30 "升级"
```

维护期间不发通知,接收端也不把失联当作告警。最长 24 小时,到期自动恢复。进入和退出都写审计。

## 验收

自动脚本是 `tests/acceptance.sh`,在 CI 的 `acceptance` 作业里对真实安装的服务运行。

| 编号 | 操作 | 预期 |
|---|---|---|

| T-04 | SIGSTOP | 看门狗超时后重启 |

| T-07 | 替换程序 | 启动失败,外部比对告警 |

| T-10 | 断开网络 | 报失联,恢复后补发 |

| T-12 | 向 IPC 发畸形数据 | 拒绝,不崩溃 |

## 剩余风险

| 编号 | 风险 |
|---|---|
| R-S1 | 内核级攻击者可绕过本地一切措施 |
| R-S2 | 持有心跳密钥的完全接管者可伪造心跳 |
| R-S3 | 网络分区时外部无法区分断网和被攻破 |
| R-S4 | 接收端本身成为攻击目标,需要独立加固 |
| R-S5 | 配置和程序的哈希记录在本机,能改写记录的人也能绕过本地校验 |
| R-S6 | 心跳密钥在本机以文件保存 |

## 用 sudo 运行

`sudo` 运行时,配置和数据放在 root 自己的主目录,不再用调用者的 `~/.config`。root 只读取 root 所有、其他人不能写的配置文件。否则任何以该用户身份运行的程序都能改写配置里的 `command` 报警,让 root 去执行,这是提权漏洞。

所以 `sudo` 和普通运行各有一份设置,互不影响。

## 隐私

命令行、环境变量和日志里常有密码和令牌。证据写入、审计和报警之前都经过脱敏:`--password x`、`token=x`、`Authorization: Bearer x`、URL 里的密码、常见令牌格式都会替换为 `***`。这是基于模式的,不保证发现所有秘密。

`privacy.redact` 可以在设置中关闭,默认开启。`privacy.command_lines` 关闭后,实时检测仍按命令行判断,但不再保存或发送命令行内容。

诊断包(`--diagnose`)不含 webhook 地址和令牌。
