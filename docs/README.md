# procwatch 文档

procwatch 是一个终端里的进程分析与调查工具,支持 macOS、Linux 和 Windows。它把进程监控、持久化枚举、时间线、检测规则、证据管理和操作级活动采集放在同一个界面里。

## 验证状态的含义

文档里凡是说到“能做到”,都尽量注明验证到什么程度:

| 标记 | 含义 |
|---|---|
| **真机** | 在真实的交互式系统上使用过 |
| **CI 实测** | 在 GitHub Actions 虚拟机上实际运行并测得结果 |
| **待 CI** | 代码已写完并通过编译和单元测试,等待下一次 CI 运行 |
| **仅类型检查** | 只通过了编译,从未运行过 |

目前只有 macOS 属于“真机”。Linux 和 Windows 只在 CI 的无界面虚拟机上运行过,Windows 是 Server 版,不是桌面系统。

## 明确的设计边界

这些不是待办事项,而是有意不做的:

- **不读取进程内存内容**,不做内存转储。
- **不注入代码,不做 API hook**,不写其他进程的内存。
- **不把文件上传给第三方**,没有在线信誉查询。
- **隔离脚本只生成,不执行**。网络隔离可能切断你和被调查主机的连接,必须由人决定。
- **拦截默认关闭**,必须显式给出策略文件,而且策略默认只审计。
