# 故障排查

先按 `H` 看采集健康页,大多数“看不到数据”的问题都会在这里解释。然后运行 `procwatch --selftest`,它测量这台机器上每个来源实际能看到什么。

| 现象 | 原因 | 处理 |
|---|---|---|
| Activity 页提示 needs root / 需要管理员 | 采集使用特权接口 | 用 `sudo` 或管理员运行 |
| Windows 上 Network 列全为 0 | ETW 需要管理员 | 以管理员运行 |
| Linux 上部分进程流量为 0 | 无权读取 `/proc/<pid>/fd` | 用 root 运行;UDP 不被统计 |
| Linux 深度追踪漏掉极短命的进程 | 非 root 时是 20 ms 轮询 | 用 root 运行,切换到内核事件 |
| 采集显示大量 dropped | 超过每秒 2 万条 | 缩小范围,或接受采样结果;结论要考虑缺口 |
| `--enforce` 提示 would also match … | 规则会匹配系统必需文件 | 把路径写得更具体 |
| `--enforce` 提示 needs a kernel driver | 这个平台做不到该规则 | 见[拦截与策略](enforcement.md) |
| `--enforce` 以退出码 3 结束 | 回答线程卡住,看门狗为保护系统主动退出 | 查看磁盘或系统负载 |
| 重复启动后 ETW 失败 | 崩溃遗留的会话 | procwatch 启动时会清理;两个实例不能同时采集,后启动的会接管 |
| 终端显示异常 | 终端太小或编码问题 | 放大窗口;任何尺寸都不应崩溃,若崩溃请报告 |

## 卡住时

- `--soak` 带看门狗,卡住时打印最后所在阶段。
- 界面上按 `ctrl+c` 或 `q` 退出,终端会被恢复。
- `--enforce` 用 `ctrl+c` 或 `kill` 结束,所有拦截立刻消失。

## 已知性能现象

Windows 上 sysinfo 的进程列表刷新平均约 1.2 秒,最长约 5.3 秒,所以实际采样约 2 秒一次。这在后台线程,不影响界面响应,原因尚未定位。
