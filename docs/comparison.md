# 与专业工具对比

这份对比按“procwatch 的目标是高级计算机监护仪,并扩展到 Linux 服务器攻击报警”来评判,不降低标准。

结论先说:**作为一体化的单机工具,它已经有独到之处;但在任何一个单项上,它都还没有超过该领域最好的专业工具。** 市面工具经过多年真实环境打磨,procwatch 的许多能力只在测试中验证过。

评级:**领先** 明确好于对比对象;**接近** 主要场景够用;**落后** 有但差距明显;**缺失** 没有。

## 分项对比

| 领域 | 对比对象 | 评级 | 差在哪 |
|---|---|---|---|
| 进程详情 | Process Explorer、System Informer | 接近 | 没有 GPU 引擎细节;Windows 无空闲线程实时栈(项目边界) |
| 操作级活动 | Procmon | 落后 | 符号只到导出函数;ETW 会丢事件;待 Windows 实测 |
| 句柄 | handle.exe | 接近 | 不显示命名管道名称 |
| 网络连接 | TCPView、ss | 接近 | |
| 抓包 | Wireshark、tcpdump | 落后 | 只存文件,无解析和过滤表达式 |
| 入侵检测 | Suricata、Zeek | **缺失** | 没有协议解析和流量特征,只有 SYN 头 |
| 系统调用监控 | Falco、Tetragon | **落后很多** | 没有 eBPF,进程检查是 30 秒轮询,短命攻击看不到 |
| 自启动项 | Autoruns | 落后 | 类别更少 |
| 进程事件日志 | Sysmon | 落后 | 无驱动;Linux 依赖 netlink |
| 主机入侵检测 | Wazuh、OSSEC | 落后 | Wazuh 有数千条规则和集中管理;这里约 40 条 |
| 登录防护 | fail2ban | 接近 | fail2ban 支持的服务更多;这里多了攻击链和慢速猜测 |
| Web 防护 | ModSecurity、WAF | **缺失** | 只读访问日志,不能阻止,看不到正文 |
| 文件完整性 | AIDE、Tripwire | 落后 | 只监视关键路径,不覆盖整个系统 |
| Rootkit 检测 | rkhunter、Lynis | 落后 | 只有两种视图比对 |
| EDR | CrowdStrike、SentinelOne | **落后很多** | 无云端情报、无行为模型、无内核传感器、无集中管理 |
| 内容规则 | YARA | 接近 | 完整语法;只扫磁盘文件 |
| 日志规则 | Sigma | 落后 | 子集,无聚合 |
| 指标 | Prometheus、Netdata | 落后 | 30 天分钟级,无图表;可用 Grafana 接入 |
| 监控告警 | Zabbix、Alertmanager | 落后 | 无值班轮换、确认和升级 |
| 舰队管理 | Wazuh、osquery fleet、Velociraptor | **缺失** | 只看本机 |
| 容器 | Falco、Datadog | **缺失** | 不识别容器和 Kubernetes |
| 取证流程 | Velociraptor、KAPE | 接近 | 保管链和离线分析都有;无跨主机 |
| 内存取证 | Volatility | **不做** | 项目边界 |
| 信誉情报 | VirusTotal | **不做** | 项目边界 |

## 独到之处

这些是组合上的优势,单项工具通常不会同时具备:

1. **一个程序覆盖从监控到取证。** 看进程、看流量、发现攻击、封证据、出报告,都在同一个文件里,不需要装一套 ELK。
2. **跨数据源的攻击链。** 把端口扫描、SSH 爆破、Web 攻击、反弹 shell、新增密钥串成一条攻击。fail2ban、AIDE、Suricata 各看一段。
3. **成功才升级。** 攻击被拒绝和被响应是两回事,严重度随之变化。
4. **按星期小时学习的基线**,不用配阈值,且不会把攻击学成常态。
5. **防误伤设计。** 默认审计、封禁自动过期、登录中的管理员永不被封、哈希链日志。
6. **诚实的能力声明。** 每个模块说明什么在这台机器上不可用,以及为什么;缺的数据显示 n/a 而不是 0。
7. **三平台同一套流程和文档。**

这些优势需要真实服务器长期运行来证明,目前还没有。

## 补全优先级

按对“服务器受攻击报警”这个目标的价值排序:

| 优先级 | 项目 | 为什么 |
|---|---|---|
| 1 | eBPF 传感器 | 把 30 秒轮询变成实时,看到每次 `execve`、`connect`、`open`。最大的短板 |
| 2 | 真实服务器试运行 | 不测误报率,规则就不能信 |
| 3 | 中心端和舰队管理 | 一台台看无法管理服务器群 |
| 4 | 容器识别 | 服务器大多跑容器 |
| 5 | Windows 服务器:RDP 爆破、账户事件 | 服务器目标的另一半 |
| 6 | 协议解析:DNS、HTTP、TLS SNI | 向 Suricata 靠近 |
| 7 | 规则扩充,兼容 Falco、Wazuh 规则格式 | 数量上追不上,只能借用 |
| 8 | 告警确认、升级和值班 | 从“能报警”到“能运营” |
| 9 | 数据库、Redis、Nginx 等服务监控 | 监护仪的完整性 |

## 什么时候用 procwatch

- 需要在一台机器上快速调查,并保留可校验的证据。
- 中小规模服务器,想要一个文件就有监控、攻击报警和取证。
- 需要在三个操作系统上用同一套流程。
- 没有条件部署 ELK 或商业 EDR。

## 什么时候不要用

- **需要防御有针对性的真实攻击者时,不能替代商业 EDR。** 攻击者拿到 root 后可以结束它。
- 合规要求经过认证的产品。
- 需要管理很多台机器。
- 需要内存取证。
